Phase 1

Ingestion & Storage

1User uploads high‑res drone GeoTIFF via the React SPA. 2Node.js API Gateway uploads raw asset to S3 Object Storage. 3Project metadata recorded in PostgreSQL database.
▶
Phase 2

Async Job Queuing

1API Gateway pushes a processing job (S3 URI) into the Redis Task Queue. 2Frontend switches to "Processing" state, listens via WebSocket / HTTP polling. 3System remains fully responsive during heavy AI computation.
Phase 3

AI Inference & Geospatial Extraction

1Semantic Segmentation — U‑Net predicts building footprints via TorchServe. 2Boundary Detection — Canny Edge + HoughLinesP extract fences, walls, roads. 3Constrained Tessellation — Watershed generates parcels bounded by physical barriers. 4Topology‑Aware Vectorization — Shapely converts to GeoJSON with confidence scores.
▶
Phase 4

Persistence & Delivery

1Vector shapes stored in PostGIS; static GeoJSON uploaded to S3. 2Python worker updates task status in Redis. 3API Gateway notifies the React frontend of completion. 4Frontend renders interactive cadastral overlay on the map.

Risks & Mitigations
SIH
Smart India
Hackathon
2026
⚡Heavy Compute Loads
Mitigated by decoupling the AI pipeline via Redis/RQ and using Kubernetes to auto‑scale GPU worker nodes during peak traffic. Spot instances provide cost‑efficient burst capacity.
📤Large File Uploads
Mitigated by implementing resumable, chunked uploads via the Node.js Fastify API directly to S3. Progress tracking and retry logic ensure reliability over unreliable networks.
⚖️Legal / Accuracy Risks
Mitigated by explicitly tagging boundaries with a "confidence score" (High vs. Low) in GeoJSON metadata, enforcing a mandatory human‑in‑the‑loop review before any parcel is approved. Full audit trail maintained.
